# 网关身份恢复

当网关签名密钥、消息代理凭据、凭据代次或受信任的云端密钥无法再安全使用时，使用本手册。

AetherEdge 现已实现本地文件型注册客户端和 `claimed` 公钥绑定状态。与之配套的生产级 AetherCloud Claim 端点、活动凭据签发、硬件支持的密钥保管和密钥轮换尚不是生产能力。因此，恢复仍然需要操作员和 AetherCloud 凭据权威方参与；静态文档不能签发或授权替换身份。

当前 Linux 基线把身份材料存放在 `<data-directory>/uplink/identity` 下，目录权限为 `0700`，文件权限为 `0600`。这只是普通的文件保护，不是 TPM、Secure Enclave、系统密钥环、HSM 或硬件支持的保管。

## 遏制

1. 禁用可选的 CloudLink 和受治理控制组合。本地采集、确定性规则和已投运的安全行为必须在没有云端的情况下继续运行。
2. 通过各自所属的系统撤销受影响的消息代理凭据和云端凭据。不要把替换用的机密放进配置文件、日志、可见或不受信任的提示，或者智能体对话记录。注册令牌只能通过 `aether cloud enroll` 的隐藏终端提示或显式的 `--token-stdin` 机密管道输入；私钥绝不能进入任何提示。
3. 保留网关 ID、凭据 ID 与代次、最近一次被接受的会话代次、质询账本证据、CloudLink Spool、审计记录，以及调查所需的时间戳。
4. 如果私钥可能已经泄露，不要复用该密钥，也不要只是重启旧会话。

注册存储会有意拒绝覆盖不同的身份或已认领的身份。在云端身份和凭据被撤销、调查证据得到保全之前，不要通过删除或编辑文件来绕过这道保护。

## 重新建立信任

1. 撤销云端的公钥绑定以及所有派生凭据。在更改本地状态之前，先就替换用的网关身份和代次达成一致。
2. 为旧身份元数据和审计证据保留一份受保护的取证副本。绝不要把私有种子复制到工单、日志、Shell 历史或智能体对话记录中。
3. 只能通过经批准的恢复流程和真实的注册应用路径重新建立本地身份。当前 CLI 有意不提供强制重置或强制覆盖选项。
4. 置备一个由服务管理器管理的新 CloudLink 机密引用，并在需要时置备新的密钥和凭据代次。
5. 只更新显式的身份和机密引用设置。绝不要根据凭据的形态推断提供方或身份。
6. 启用连接器之前，针对确切的网关身份核对消息代理主体和主题授权。
7. 只启动一个连接器实例，并让它独占自己的会话代次、质询账本和 Spool 文件。
8. 确认出现了新的质询和已签名的网关 hello、严格更新的已接受会话代次，以及成功的已签名心跳或持久上行证据。
9. 在只读遥测、审计交付、凭据代次和边缘端本地策略全部检查完毕之前，保持受治理控制处于禁用状态。

当前的 `session-accepted`、心跳确认和应用确认仍然存在已记录在案的认证缺口。实验性重连成功并不是生产身份证明。
