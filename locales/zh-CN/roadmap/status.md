# 平台状态与路线图

状态按已经实现、实验性和规划中的能力分别报告。产品名称不会提高技术成熟度。

## AI 原生最终用户体验

**已经实现的基础**：面向智能体的 Markdown 与索引、智能体技能、运行时能力发现、OpenAPI、受治理应用命令、AetherEdge MCP 工具与资源、确定性本地规则、审计证据，以及公开契约与一致性仓库。

**实验性或部分实现**：AetherCloud 的传输中立 MCP 应用接口、期望/上报/应用部署、受治理作业、CloudLink、遥测持久化，以及 Edge 与 Cloud 的开发测试装置。

**规划中**：家庭或站点语义上下文、最终用户对话智能体、类型化意图/方案/策略契约、意图到自动化编译器、历史仿真、按需生成的确认体验、临时行为有效期、效果评估和持续受治理调整。当前任何发布版本都不应把这些能力描述成完整的产品。

## AetherEdge

**已经实现**：六服务运行时、SHM 实时状态权威、嵌入式本地运行、受治理命令、`aether` CLI、`aether-edge-sdk`、Pack v1、MCP 与 OpenAPI 基础、已签名的 `v0.0.1` 源码/运行时/CLI/SDK 制品，以及本地的网关登记客户端。登记切片已有进程级证据，覆盖密钥生成、持久的待处理状态、严格的本地 HTTP 认领，以及由此得到的 `claimed` 身份状态。

IO 源码树中除了已有的 DL/T 645 实现之外，还包含需要显式启用的 BACnet/IP、CJ/T 188、IEC 60870-5-101、GB/T 32960 和 JT/T 808 适配器切片。COMTRADE CFG/DAT 检查和 CSV 归一化是离线的 CLI 功能，而不是 IO 协议。这些切片都有编解码器和工厂证据，BACnet/IP 和两个入站终端服务器还有环回交换证据；与设备厂商的互操作性以及现场投运仍属于各部署自己的证据，而不是面向整个仓库的认证声明。[协议适配器参考](/zh/reference/protocol-adapters)记录了每个适配器当前的证据等级。

**实验性**：归上行服务所有的 CloudLink MQTT v1 基础、由应用 ACK 驱动的待发送队列、AetherContracts alpha.4 消费，以及真实消息代理的开发证据。Edge 的真实消息代理测试装置现在要求云端签名的质询和网关签名的 hello；旧版的直接 hello 会被拒绝。旧版 MQTT 仍是运行时默认值。

**规划或受门槛限制**：部署与之匹配的 AetherCloud 生产 认领端点、可验证的凭据签发与激活、云端信任密钥的下发与轮换、生产 `aether-uplink` 身份组合、生产 CloudLink 密钥生命周期、签名 ACK、完整的联合一致性、旧版切换、历史查询的归属，以及剩余的应用边界迁移。Home Assistant 和 SunSpec 的实现属于树外的下游工作，不是内核路线图上的能力。

本地的 `claimed` 登记状态只表示一个经过测试的 认领服务器确认了所提交的公钥指纹。它不是 `credential-active`、`cloudlink-connected` 或 `online`，也不声称已与生产 AetherCloud 完成配对。

**CloudLink alpha.4 生产阻塞项**：当前的 `session-accepted` 消息没有签名，既不携带 `challenge_id`，也不携带 `client_nonce`。仅限 Edge 的测试装置把接受步骤排在已验证的质询之后，并要求持久化的会话纪元严格递增，但生产的上行运行时尚未组合这条会话路径，也没有把断开连接与握手取消绑定在一起。即便是这些测试检查，也无法从密码学上排除来自另一次握手的延迟接受消息。公开的线上契约必须把经过认证的接受消息与当前完整的握手记录绑定，这条路径才能被称为生产认证。

当前的 AetherCloud 双产品测试装置同样卡在这一步之前：它的工作进程仍然组合旧版的直接会话应用路径，没有注入质询签发或网关签名的会话接受。AetherEdge 保持严格验证开启，宁可超时也不降级。

## AetherCloud

**已经实现的基础**：模块化单体领域与应用切片、能力驱动的提供方、仅规划的 OpenTofu、网关登记的领域与应用基础、部分 CloudLink 与遥测持久化、制品/部署/作业基础、审计与集成切片、可观测性，以及传输中立的 MCP 接口。

**实验性或部分实现**：MQTT 编解码与入口、本地和 AWS IoT 测试装置、PostgreSQL 已接受遥测 ACK 发件箱，以及有限的审计接口。

**规划或受门槛限制**：与之匹配的生产网关 认领端点、生产身份与凭据签发、完整的 CloudLink 持久性与映射、生产组合和工作进程、公开的作业/部署交付、加固的出站集成，以及可连接的 MCP 服务器。

## AetherContracts

**已经实现但仍属实验性**：alpha.3 规范、封闭结构定义、测试夹具、TCK、按摘要固定的使用方验证，以及四种测试夹具绑定。

**规划或受门槛限制**：生产认证密钥生命周期、签名的持久 ACK、完整的生产编解码器，以及用于生产 CloudLink 切换的发布版本。

## 平台文档

**本次迁移中已经实现**：共享的产品概览、统一导航、部署拓扑、用户旅程、端到端 alpha 联动任务、兼容性矩阵、状态页面，以及 AetherIot 到 AetherEdge 迁移指南。

**规划中**：自动化的跨仓库版本聚合、发布通道状态源，以及在有合适地址时建立未来的 GitHub 组织。
