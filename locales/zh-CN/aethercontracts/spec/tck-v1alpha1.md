# 语言中立 TCK v1 alpha 1

> 本页帮助中文用户理解协议。带标签版本中的英文规范、JSON Schema、测试夹具和 TCK 才是规范性依据。

仓库测试会编译所有规范性 JSON Schema，验证有效与线结构无效的测试夹具，保留上下文无效这一独立区分，并校验每一项声明的 SHA-256。

仓库参考运行器执行已发布的核心场景，覆盖整数优先级、严格原始 JSON、业务摘要与 Runtime Manifest 摘要、最小的会话、重放和确认上下文、数据丢失与游标规则，以及 Thing Model 键冲突。Integration 场景还冻结拓扑身份和引用解析、精确的快照代次绑定、点位值类型匹配、质量与值的存在关系，以及规范有符号整数、十进制和 Base64url 边界。参考运行器不是生产 CloudLink 或提供方状态机。线结构无效夹具目前证明结构性拒绝；从结构定义到失败代码和 JSON 路径的精确映射仍在规划中。

认证 TCK 还冻结封闭的 `session-challenge-request` 契约面、其既有的 `up/session` MQTT 路由、默认关闭且不构成认证的请求策略、对已持久化质询的精确重试、严格的 `evaluation_time_ms < expires_at_ms` 截止时间，以及与会话接纳一起原子完成的一次性质询消费。其语言中立的上行参考实现冻结精确的交付与心跳签名投影、显式 null 规则、已接纳会话的心跳新鲜度、带溢出检查的 uint64 运算、不刷新存活状态的心跳重放，以及与会话无关的交付重放。交付场景冻结不可变重放投影、同一会话内的精确重放、向严格更高会话代次的重新绑定、同代次会话冲突、会话代次回退、旧会话拒绝、凭据代次不可变性，以及重启后保持稳定的单一绑定状态。这些场景保持四字段线协议重放身份不变，同时证明按命名空间分区的记录相互独立，并且跨命名空间的记录会被拒绝；命名空间是可信入口上下文，绝不是载荷数据。它们还证明，已提交的业务事实可以在原始到期时间之后重新绑定并恢复其当前会话的持久确认，而已到期的首次交付或待定的认证记录不可以。冲突会在持久重放记录的到期检查之前报告为 `AUTHENTICATION_INVALID`，并且绝不重复业务效果。所有评估时间和协商得到的心跳间隔都是显式的场景输入；运行器绝不读取环境时钟。TCK 辅助函数是纯归并器：`committed_delivery` 是前置条件，表示业务效果和重放记录已经原子提交，而它返回的下一状态在调用方提交之前并不持久。TCK 还断言 alpha.4 的 `session-accepted` 没有签名，也没有握手关联，因此不满足规划中的生产门槛。Integration Control 夹具拒绝长度超过 128 个字符的回执 `failure_code` 值。

持久确认场景冻结累计连续前缀行为：乱序的持久位置不能越过未声明的缺口推进，针对完全相同流代次的有效数据丢失证据可以解决中间缺口，来自其他代次的证据不可以，而之后的持久补齐允许游标推进。参考运行器使用显式给出的已持久位置和丢失区间；它不推断存储状态。

CloudLink Integration 测试还冻结公开载荷的原样封装、入口结构定义判别、经认证的外层网关身份、不可变的流与批次绑定、拓扑代次顺序、精确的持久确认绑定、机密拒绝和完整消息大小预算。它们不能证明产品数据库事务、消息代理部署或重启恢复。

Integration Control 测试冻结独立且默认关闭的启用方式、唯一的封闭动作 `device.power.set.v1`、精确拓扑目标、强制的治理与确认证据、云端签名投影、作业重放绑定和提供方回执证据。它们从结构上拒绝任意提供方操作、URL、令牌和物理完成声明。它们不能证明产品对 Home Assistant 的调用，也不能证明物理执行器的结果。

可移植黑盒运行器协议计划采用通过标准输入和标准输出传输的 NDJSON。操作包括 `validate`、`canonicalize`、`digest`、`verify-signature` 和 `check-compatibility`。它将比较是否接纳、稳定失败代码、JSON 路径、规范字节、摘要和状态结果；不会比较特定语言的错误说明文字。

TypeScript、Rust、C 与 C++ 在各自执行相同的清单和场景集合之前仍属实验性。真实消息代理双端测试和破坏性故障注入是独立的、需主动启用的证据，绝不进入默认离线测试路径。
