# 物联网业务遥测

> 权威来源：[AetherCloud](https://github.com/EvanL1/AetherCloud/blob/main/docs/concepts/iot-telemetry.md)。此页面镜像到统一的 AetherIoT 文档中。

协议中立的领域、应用层的摄取与历史用例、规范批次摘要、内存一致性适配器、实验性的 CloudLink MQTT 点位批次映射，以及 PostgreSQL 遥测适配器已经实现。PostgreSQL 切片以原子方式保存重放身份、流与游标状态、已接受的业务事实、审计、集成发件箱和精确的持久 ACK 发件箱。它在 PostgreSQL 18 上证明了提交前回滚和提交后相同 ACK 的恢复。公开 HTTP 历史、生产数据库组合、联合生产认证、多样本映射和持久的数据丢失记录仍在规划中；内存适配器不构成生产持久性声明。

物联网业务遥测是租户拥有的产品数据。它不是 OpenTelemetry 运维数据。AetherEdge 运行时仍然是当前实时点位值的权威；AetherCloud 保存重放安全、带时间戳的历史事实和带新鲜度标记的投影。

## 领域边界

第一个切片使用明确的资源，而不是通用实体表：

- `TelemetryStream` 标识网关的一条有序逻辑上行流。
- `StreamEpoch` 在有意重置流之后隔离序列复用。
- `StreamPosition` 是无符号 64 位值，在 JSON 边界编码为规范十进制字符串，在 TypeScript 中无损表示。
- `TelemetryBatch` 是原子摄取单元，拥有一个有界的有序记录列表。
- `PointSample` 携带实例与采集点位身份、来源时间、类型化值和来源质量。只接受 `telemetry` 和 `status` 两种点位类型；命令或动作类型不能成为控制后门。
- `TelemetryTopologyBinding` 为每个批次保留边缘发布纪元和带算法限定的拓扑快照摘要。
- 物模型引用是可选的，并且必须来自已投运的证据；AetherCloud 不会为边缘原生点位臆造引用。
- `DeviceEvent` 携带版本化的事件类型、来源时间和有界的类型化载荷。
- `IngestionReceipt` 记录批次身份、摘要、持久游标、接受状态和云端持久化时间。
- `RetentionClass` 选择一项经过授权的保留策略；调用方不能提供任意存储时长。

AetherEdge 目前暴露数值型采集样本和四种质量状态。云端值模型可以为未来的物模型设计得更宽，但第一版传输契约不得声称边缘端无法发出的值变体。

## 可信身份与范围

CloudLink 在调用摄取用例之前，先从经过认证的活动网关凭据解析出租户、项目、网关和凭据代次。信封可以重复这些标识符以便关联，但载荷字段绝不是授权证据。已暂停或已吊销的凭据代次会以失败关闭方式被拒绝。

应用命令是 `telemetry.batch.ingest`。它要求网关凭据范围、有效期、幂等性、审计、有界大小，以及由应用拥有的存储库与收件箱事务。HTTP、测试夹具或未来的其他传输都必须调用同一个命令，而不是直接写入历史。

## 批次身份、摘要与原子性

已实现的稳定身份是：

```text
TenantId + ProjectId + GatewayId + StreamId + StreamEpoch + first position
```

规范载荷摘要覆盖版本化的业务内容，不覆盖传输头、追踪上下文、重试次数、套接字身份或压缩字节。

MVP 以原子方式接受完整批次。校验、限制、授权、记录唯一性、摘要计算、序列评估、收件箱身份、业务事实、必需的审计和发件箱事件在同一个事务中全部成功，否则全部不被接受。未来的部分记录模式需要新的契约版本和逐条记录的回执。

## 重复、冲突、缺口与乱序行为

- 身份和摘要都相同的是重复批次。它返回此前的持久确认，不会再次创建历史或集成事件。
- 身份相同但内容不同的是冲突重复。它会被隔离并审计，绝不会被确认为已接受。
- 下一个连续批次在事务提交后推进持久游标。
- 前向缺口会被持久记录、可观测，并请求重放。它不会推进连续确认游标。
- 有界的乱序窗口可以把较晚的批次保留为待处理。禁止无界缓冲。
- 早于持久游标的批次要么是经过验证的重复，要么是冲突；仅凭时间早晚绝不能证明内容相同。
- 边缘端的保留溢出会成为明确的丢失或缺口标记。任何一端都不会伪造缺失的样本。

## 持久确认

`received`、`decoded`、`validated`、`accepted`、`durably persisted` 和 `acknowledged` 是互不相同的观测。只有包含去重身份和已接受业务事实的事务提交之后，CloudLink 才可以发送成功的持久确认。

如果连接在网关收到该确认之前失败，网关可以安全地重放该批次。提交之后发生崩溃时，重放会返回相同的回执。存储超时且提交结果未知时，必须先通过幂等身份查明结果，才能尝试任何新的接受。

已实现的 PostgreSQL 路径在同一个事务中保存精确的 alpha.3 ACK 投影。有界的交付工作进程使用 `FOR UPDATE SKIP LOCKED` 租用待处理行，按顺序发布，只在发布成功后才标记已交付，并释放失败的行以便有界重试。重放会把相同的事件 ID、回执 ID、持久化时间、流位置、批次 ID 和摘要重新入队；它绝不会臆造第二个业务事实。应用在发布之前，会在适配器边界校验所有领取到的行。

## 时间与新鲜度

每条记录至少保留：

- 边缘或来源事件时间
- 云端接收时间
- 云端持久化时间
- 流纪元和位置
- 来源质量

历史查询会暴露来源时间和摄取时间。最新值投影还会暴露它的持久位置、新鲜度和已知缺口状态。它绝不会被标记为当前物理值。迟到的数据保留在事件时间历史中，但不能悄悄让最新值投影倒退。

## 存储职责

`PostgresTelemetryRepository` 现在拥有流元数据、持久收件箱身份、连续游标、缺口状态、保留策略、有界历史、审计、集成发件箱和 CloudLink ACK 发件箱的第一个有界实现。租户范围内的键和强制行级安全是纵深防御；常规应用角色仍然不是超级用户，也不具备 `BYPASSRLS`。

当体量足够大时，按内容寻址的原始批次、冷批次和导出由对象存储负责。大规模历史、聚合和降采样由未来的时序或分析适配器负责。这两种存储都不会成为实时状态权威。

历史端口归遥测应用上下文所有，因此经过实测的摄取热路径可以迁移，而不改变领域契约。

## 资源与安全限制

解码器拒绝不受支持的契约版本、不安全的整数编码、非有限的数值样本、未知的记录变体、批次内重复的位置、过多的记录、过大的值、解压膨胀和无界元数据。配额拒绝和背压是可见的结果，而不是静默丢失。

禁止把 TenantId、ProjectId、GatewayId、PointId、原始载荷和任意事件类型字符串用作 OpenTelemetry 指标标签。登记令牌、凭据、私密材料和授权头绝不进入遥测载荷、错误、日志、追踪或审计详情。

## 应用接口与状态

- 命令 `telemetry.batch.ingest`：领域与应用、内存和 PostgreSQL 适配器已实现。
- 查询 `telemetry.history.query`：应用、内存和有界 PostgreSQL 适配器已实现。
- 事件 `telemetry.batch-accepted.v1`：内存和 PostgreSQL 事务性发件箱行为已实现。
- 精确的 CloudLink 持久 ACK 发件箱和有界交付用例：已针对已接受的遥测实现；生产工作进程组合仍在规划中。
- 流游标、缺口、滞后和保留状态查询：规划中。
- CloudLink MQTT 适配器：实验性的编解码器、桥接与入口，以及共享的 alpha.3 AetherEdge 测试夹具清单已实现；桥接使用已持久化的 ACK 投影，而生产数据库与工作进程组合以及会话持久化仍在规划中。
- HTTP 历史适配器：规划中。

阅读[运维可观测性](/zh/aethercloud/concepts/operational-observability)，了解为什么追踪、指标和日志要与持久的物联网遥测保持分离。
