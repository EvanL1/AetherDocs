# Home Assistant 集成

> 权威来源：[AetherCloud](https://github.com/EvanL1/AetherCloud/blob/main/docs/concepts/home-assistant-integration.md)。此页面镜像到统一的 AetherIoT 文档中。

[英文版](https://docs.aetheriot.ai/aethercloud/concepts/home-assistant-integration/)

Home Assistant 在 AetherEdge 一侧集成，靠近家庭网络和设备。AetherCloud 不连接用户的 Home Assistant 实例，不保存其令牌，也不成为设备当前状态的权威来源。

目标数据链路如下：

```text
Home Assistant
  -> AetherEdge connector
  -> vendor-neutral integration topology and observations
  -> governed CloudLink delivery
  -> AetherCloud projection
  -> Agent discovery and explanation
```

这条只读链路已经可以在显式启用的源码构建中运行。AetherEdge 可以通过相互独立、可跨崩溃恢复的 CloudLink 流生成严格的 alpha.4 候选版拓扑与观测消息。AetherCloud 验证当前会话和运行时清单声明后，以原子方式保存业务投影、重放回执、审计证据、发件箱证据和连续应用确认。

它仍是实验性集成，不是已经发布的家庭产品。契约还是未发布的候选版本，部分云端组合适配器仍基于内存，可选的智能体查询适配器还没有公开的网络服务，生产级登记和凭据生命周期也尚未完成。云端入口自身也不做任何网关认证，而是完全依赖你的消息代理上按网关配置的 ACL，详见[云端入口的认证依赖你的消息代理 ACL](#云端入口的认证依赖你的消息代理-acl)。

## 权威与机密边界

| 事项                                         | 权威来源                                          |
| -------------------------------------------- | ------------------------------------------------- |
| Home Assistant 注册表和实体观测状态          | Home Assistant 提供证据，由 AetherEdge 在本地消费 |
| 归一化、重连、重新同步和本地接纳             | AetherEdge                                        |
| 实时点位状态、确定性规则、安全和物理执行     | AetherEdge                                        |
| 共享的拓扑和观测结构                         | AetherContracts                                   |
| 可搜索的历史投影和智能体上下文               | AetherCloud                                       |

Home Assistant 的 URL、访问令牌、刷新令牌和 OAuth 客户端材料只能保留在边缘本地配置或机密提供方中。它们不得进入拓扑、观测、CloudLink 载荷、云端持久化存储、审计详情、日志、提示词和智能体上下文。

## 云端入口的认证依赖你的消息代理 ACL

这条链路的云端一侧运行在一种刻意受限的 CloudLink 模式下。完整说明见 [CloudLink 可靠传输与生命周期](/zh/aethercloud/concepts/cloudlink-and-core-state-machines)，但即使只读到本页，也必须了解下面的约束。

云端入口不验证任何网关签名，无论是建立会话时还是之后的任何上行消息，因为目前还没有生产级的消息来源密钥源。它改为根据消息中携带的网关 ID、凭据 ID 和凭据代次，解析出一份由操作员配置的凭据。这三个值都是非机密标识符。配置的机密从不经过网络传输，AetherCloud 也从不保存它。

- **认证完全依赖消息代理一侧按网关配置的 ACL。没有这些 ACL，就等于没有认证**。任何能够写入某个网关的上行主题并且知道这三个标识符的发布者都能获得会话，随后可以上报运行时清单，并覆盖该网关已投影的家庭拓扑和观测。
- **入口登录消息代理所用的账号不是按网关配置的 ACL**。可选的消息代理用户名和密码认证的是 AetherCloud 自己到消息代理的订阅者连接，并不说明哪些发布者可以写入某个网关的上行主题。本仓库中没有任何内容配置、强制或验证这些 ACL，无论你是否创建了它们，入口都会启动。
- **不使用任何发布者证明**。经过评审的受信连接器可以在带外为每次发布提供经过验证的发布者证明，而这一组合完全不使用它。它假定消息代理 ACL 是正确的，并且无法发现 ACL 不正确。

因此，把每个网关的消息代理凭据限制在该网关自己的主题命名空间内，是必需的部署步骤，而不是可选的加固措施。这种模式适合单个家庭：消息代理归你所有，并且你可以在带外确认发布者身份。它不是网关认证，不得被描述为网关认证，也不支持多租户或多网关规模。

## 契约候选版本

当前相邻工作区中的 AetherContracts `0.1.0-alpha.4` 定义了闭合且与提供方无关的 `aether.integration` 契约：

- 带无损代次的完整拓扑快照；
- 区域、设备、实体，以及每个实体下的多个类型化点位；
- 以拓扑代次隔离的观测批次；
- 精确的 `int64`、`uint64`、十进制数、有限浮点数、字符串、布尔值和 base64url 字节值；
- 明确的 `good`、`uncertain`、`bad` 和 `unavailable` 质量；
- 对重复身份、悬空引用、类型不匹配以及无效的质量与值组合，给出带上下文的拒绝。

Home Assistant 注册表条目标识成为稳定的实体标识。可变的 Home Assistant `entity_id` 保留为 `source_address`，因此重命名不会产生新的 Aether 实体。`light`、`switch` 和 `fan` 的主电源状态是布尔点位 `is_on`。经过选择的有界属性成为单独声明的点位；任意属性不会复制到契约中。

契约刻意排除凭据、任意服务调用和 CloudLink 传输封装。设备控制需要后续单独定义、默认拒绝的能力与回执契约。

AetherCloud 现有的完整使用方锁仍固定在已发布的 `0.1.0-alpha.3` 版本。只有 alpha.4 正式发布、按精确摘要导入并通过使用方测试后，才能宣称符合 alpha.4。下文的云端领域模型与候选字段保持一致，但不能替代这道发布门槛。

## 已实现的只读链路

三个仓库目前已经具备：

- AetherEdge 中经过认证的 Home Assistant WebSocket 适配器；
- 完整快照、有序状态变化、可跨重启保持稳定的拓扑代次、显式缺口检测和完整重新同步；
- 严格的 alpha.4 候选版集成与 CloudLink 编解码器；
- 拓扑和观测各自独立的两个边缘文件日志；
- MQTT 重连和精确重放；只有收到严格的当前会话应用确认后才删除日志记录；
- 运行时清单声明，以及在新 CloudLink 会话上经过认证的恢复；
- 与提供方无关的云端拓扑和观测领域值；
- 闭合的内部命令解码，以及对存储库返回结果的深度校验；
- 由网关凭据限定范围的拓扑上报和观测上报命令；
- 由租户和项目限定范围的按标识投影查询与有界目录投影查询；
- 代次隔离、类型化值校验、重放身份和冲突结果；
- 内存和 PostgreSQL 投影适配器；
- 把集成事实、收件箱身份、不可变回执、拓扑历史、审计记录、发件箱记录、CloudLink 交付和连续确认绑定在一起的 PostgreSQL 事务；
- 跨会话、跨凭据代次的精确重放，且不会重复业务效果；
- 对提供方时间戳的有界未来时钟偏差拒绝；
- 始终报告 `edge-reported-copy` 和 `liveStateAuthoritative: false` 的视图。

目录按网关标识和集成标识排序，只返回有界的摘要字段。它帮助智能体在请求某个精确详情视图之前，先发现存在哪些投影副本。它不是实时设备清单，`receivedAt` 是新鲜度证据，不能证明当前物理状态。除非显式注入对应的应用查询，否则可选的 MCP 资源适配器保持隐藏。

内存适配器仍只用于辅助开发。PostgreSQL 集成适配器已经具备真实数据库的重启和并发测试，但当前 CloudLink 会话、运行时清单和部署组合仍包含基于内存的部分。因此仓库尚不宣称具备完整的生产云端进程。

## 重新同步

AetherEdge 先订阅，再获取初始快照，避免发现过程中发生的状态变化被静默丢失。注册表变化、删除、连接中断、无效协议数据或观测缺口都要求重新获取完整快照。AetherCloud 同样按精确的拓扑代次隔离每个观测批次。任何一端都不会猜测缺失状态、把值带入未知拓扑，也不会把 `unknown` 和 `unavailable` 伪造成字符串值。

## 当前用户可见的边界

- 已发布并按摘要固定的 alpha.4 完整使用方导入；
- 预构建的 AetherEdge 软件包、安装器配置和已发布的 Home Assistant 兼容性基线；
- 由安装器管理的登记、消息代理 ACL 模板、凭据轮换和生产机密管理器适配器；在这些能力具备之前，本集成的认证所依赖的按网关消息代理 ACL 必须手工编写和审计，AetherCloud 从不检查它们；
- 完全由 PostgreSQL 支撑的 CloudLink 会话与运行时清单生产组合；运行时清单目前只存在于内存中，因此云端重启会丢失已接受的声明，投影上行会以失败关闭方式被拒绝，直到每个网关再次上报其清单；
- 生产 API 和智能体发现入口；
- 有界的历史观测查询和完整的新鲜度模型；
- 公共契约中的楼层、标签、配置条目来源和服务能力发布；
- 可在生产环境启用的受治理控制链路；独立的 `aether.cloudlink.integration-control.v1alpha1` 电源动作是实验性的、默认关闭，并且不能宣称物理动作已经完成；
- 生产 OAuth 接入和令牌轮换。

这些剩余缺口是产品门槛。仓库测试通过不得被描述为受支持的生产部署。
