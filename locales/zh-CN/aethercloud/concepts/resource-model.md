# 资源模型

> 权威来源：[AetherCloud](https://github.com/EvanL1/AetherCloud/blob/main/docs/concepts/resource-model.md)。此页面镜像到统一的 AetherIoT 文档中。

AetherCloud 使用明确的物联网名词，而不是一张通用实体表。模型以后可以增加类型化关系，但基础的所有权和身份层级始终可见。

```text
Tenant
└── Project
    ├── CloudConnection
    │   └── DeploymentStack
    │       └── CloudResourceProjection
    └── Site
        └── Gateway
            └── Instance
                └── Point
```

## 核心资源

**租户**是安全、计费、保留和数据隔离的边界。每个被拥有的聚合和事件都包含租户身份。

**项目**为某个应用或运营团队归组站点和制品。它不能替代租户授权。

**CloudConnection** 引用一个明确选定的提供商身份和一个短期凭据来源。它记录配置和发现状态，从不记录原始的长期凭据。

**DeploymentStack** 是可以独立计划、应用、加锁和恢复的最小基础设施单元。它只属于一个云连接，并且只使用一个远程状态绑定。它的租户、项目、提供商、连接和状态键都是派生出来的，而不是由调用方重复提供。区域放置会保留其观测时间，供未来的新鲜度策略使用。领域定义已经实现；持久化和生命周期执行仍在规划中。

**CloudResourceProjection** 是 AetherCloud 对提供商资源的规范化、带时间戳的视图。对于资源的实际存在和生命周期状态，基础设施提供商仍然是权威。

**站点**是物理或逻辑上的运行位置，在网关被更换后仍然有意义。

**网关**是一个已登记的 AetherEdge 运行时身份。重新安装或更换硬件必须遵循明确的身份恢复流程。

已实现的网关基础区分注册、短期登记声明和声明领取。活动凭据绑定、CloudLink 会话、运行时健康、吊销和恢复仍是各自独立、规划中的事实。

**实例**是网关报告的边缘物模型实例。它的云端身份包含其网关上下文；边缘本地的数字标识符不是全局唯一的。

**点位**是实例内类型化的测量、状态、命令或调节点。云端保存元数据和历史投影，不保存权威的实时值。

## 身份规则

- 公共资源身份是不透明字符串，通常是 UUID。
- 边缘本地的序列值和标识符在传输契约中保留其原始整数宽度。
- 显示名称可变，绝不用作持久外键。
- 提供商身份是明确、稳定的小写标识符；绝不从凭据形态推断。
- 可移植的能力使用核心名称。提供商特有的能力使用带命名空间的标识符，使通用模型保持开放。
- 在租户之间迁移网关是一个明确的安全敏感流程，不是普通更新。
- 领域 Pack 增加类型化元数据和知识；它们不替代核心所有权层级。

## 状态词汇

`desired` 用于云端编写的目标，`reported` 用于边缘端观测，`applied` 只在边缘端报告成功激活时使用。`connected` 用于表示近期存在经过认证的会话，不能证明网关后面的设备健康。

添加新的状态名称之前，请参阅[术语参考](/zh/aethercloud/reference/terminology)。已实现的基础和明确的排除项见[网关身份与登记](/zh/aethercloud/concepts/gateway-identity-and-enrollment)。
