# 运维可观测性

> 权威来源：[AetherCloud](https://github.com/EvanL1/AetherCloud/blob/main/docs/concepts/operational-observability.md)。此页面镜像到统一的 AetherIoT 文档中。

OpenTelemetry 是 AetherCloud 进程的厂商中立观测埋点与导出边界。已经实现的有：默认的空操作实现、经过验证的环境变量选择启用、OTLP HTTP 追踪/指标导出器、内存导出器、W3C Trace Context 提取、有界的 span 处理器、低基数的遥测接入装饰器，以及故障隔离测试。实验性的 CloudLink MQTT 入口也暴露了一个中立的有界观察者，但其握手/会话/重连/ACK 信号的 OpenTelemetry 接线仍在规划中。Collector 部署以及覆盖面更广的 HTTP、数据库、工作进程和 webhook 埋点仍在规划中。

运维可观测性回答的是 AetherCloud 组件是否健康，以及时间消耗在哪里、故障发生在哪里。它不是物联网业务遥测，不是持久的命令回执，不是授权来源，也不是审计账本。

## 依赖边界

领域包和应用包不导入 OpenTelemetry API 或 SDK 类型。标准的框架/数据库埋点属于适配器和组合根。应用特有的操作名称可以通过应用层拥有的中立观察者端口或用例装饰器来观测。

API、CloudLink 和工作进程这三个根各自独立配置并关闭自己的 SDK 生命周期。默认是空操作实现。OTLP 导出和 Collector 是可选的部署选择；测试和正确的产品行为从不依赖其中任何一个。

导出器的队列和刷新都是有界的。不可用的导出器可以在有界重试之后丢弃运维信号，但不能阻塞 HTTP 命令、CloudLink 心跳、遥测持久化确认、收件箱/发件箱工作或已投运的边缘行为。

## 初始追踪

遥测接入用例的 span 已经实现。规划中的 span 还覆盖：

- HTTP 请求和应用用例
- CloudLink 身份验证、协商、会话、恢复和重连
- 遥测解码、验证、去重、持久化和确认
- 收件箱/发件箱的租约与投递
- PostgreSQL 事务
- webhook 投递
- 后台工作进程执行

W3C Trace Context 可以作为可选元数据跨越 CloudLink。追踪上下文和 baggage 从不参与消息身份、载荷摘要、排序、授权、权限、风险或租户解析。远程 baggage 使用很小的允许列表和严格的字节限制。

## 初始指标

初始的低基数目录包括：

- 活跃的 CloudLink 会话数
- 握手失败次数和重连次数
- 心跳时效和往返延迟
- 按有界结果类别统计的遥测批次和样本数
- 重复、冲突重放和序列缺口的数量
- 持久化延迟和确认延迟
- 收件箱/发件箱的积压、重试和死信数量
- 应用命令/查询的耗时和失败类别
- 工作进程耗时和有界队列深度
- 被丢弃的 OpenTelemetry 信号数量

指标属性使用有界的分类，例如服务、操作、协议版本、结果类别和部署环境。TenantId、ProjectId、GatewayId、PointId、JobId、用户身份、令牌、证书、完整 URL、载荷和自由格式的错误文本都禁止用作指标标签，因为它们会泄漏敏感上下文或产生高基数序列。

优先采用标准且稳定的 HTTP、数据库、RPC 和消息传递语义约定。产品特有的名称使用有文档记录的 `aethercloud.*` 命名空间，以及明确的稳定性/版本目录。实验性的语义约定不会在无意间成为稳定的 AetherCloud 契约。

## 日志、追踪与审计

结构化应用日志仍然是首要的日志接口，并在启用追踪时携带 trace/span 关联信息。原始物联网载荷、令牌、授权标头、私钥、证书材料和任意异常正文，在写入日志或附加到 span 之前都会被脱敏。

审计记录是不采样、租户范围的产品事实，随业务事务一起提交。追踪是经过采样、尽力而为的诊断信号。一条追踪可以引用审计事件身份，一个审计事件也可以保留追踪身份，但二者互不替代。span 成功或导出成功，并不说明业务事务是否成功。

## 采样与测试

对第一个适配器来说，头部采样就足够了。之后可以引入 Collector 侧的尾部采样，而不改变应用行为。错误和安全拒绝类的追踪可以获得更高的采样概率，而对应的审计记录仍然是强制的、不采样的。

一致性测试使用空操作观察者和内存导出器。它们覆盖上下文传播、上下文缺失、导出器故障隔离、有界队列、脱敏、被禁止的高基数标签，以及审计持久化与追踪采样之间的独立性。

阅读[物联网业务遥测](/zh/aethercloud/concepts/iot-telemetry)，了解持久的产品数据路径，以及业务事实与运维信号之间的边界。
