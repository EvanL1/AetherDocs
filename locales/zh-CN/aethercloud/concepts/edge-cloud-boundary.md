# 边缘端、AetherCloud 与提供商的权威

> 权威来源：[AetherCloud](https://github.com/EvanL1/AetherCloud/blob/main/docs/concepts/edge-cloud-boundary.md)。此页面镜像到统一的 AetherIoT 文档中。

广域连接和提供商 API 是不可靠的协调路径，不是控制总线。对每一项跨边界特性，都要先确定权威、投影和断连期间的行为，再选择传输方式。

| 事项             | 权威                | 远程表示                     |
| ---------------- | ------------------- | ---------------------------- |
| 当前点位值       | AetherEdge SHM      | 带时间戳的遥测投影           |
| 设备采集         | AetherEdge 运行时   | 连接与健康观测               |
| 本地安全和规则   | AetherEdge 运行时   | 版本化配置和审计投影         |
| 已投运的通道状态 | AetherEdge 本地存储 | 期望与已应用修订版状态       |
| 租户和用户访问   | AetherCloud         | 下发给边缘端的有界授权       |
| 机群成员关系     | AetherCloud         | 已登记的网关身份             |
| 已发布的制品     | AetherCloud         | 经过验证的本地制品缓存       |
| 作业意图         | AetherCloud         | 经本地校验后接受或拒绝的作业 |
| 物理命令结果     | AetherEdge 运行时   | 回执和审计记录               |
| 期望的云端放置   | AetherCloud         | 提供商范围内的部署计划       |
| 实际云资源       | 基础设施提供商      | 规范化清单投影               |
| 基础设施状态     | 堆栈的远程后端      | 元数据和版本引用             |
| 提供商能力       | 基础设施提供商      | 版本化的适配器能力投影       |

## 期望与已应用是两个独立的事实

部署请求改变的是云端期望状态。它不能证明边缘端已经下载、验证、激活或保留了该制品。边缘端带着证据报告已应用的修订版，云端同时记录这两个值，不会悄悄把它们调和成一致。

## 是作业，不是远程过程调用

跨越边界的工作至少携带：

- 全局唯一的作业身份
- 租户、网关和能力身份
- 类型化参数和契约版本
- 签发时间和到期时间
- 幂等键和重试策略
- 所需的权限、风险和确认证据
- 期望修订版或其他前置条件

边缘端返回状态转换，例如已接受、已拒绝、已过期、运行中、已成功或已失败。网络超时意味着结果未知；它不是重复执行非幂等物理动作的许可。

基础设施工作遵循相同的作业语义。计划是类似查询的只读操作；应用和销毁是命令，需要显式权限、已保存计划的证据、幂等控制、确认策略和审计。

## 断连行为

边缘端持久缓冲有界的上行数据，继续执行本地行为，并带着明确的恢复位置重新连接。云端容忍重复交付，只确认它已经持久接受的数据。保留溢出必须可观测，不能被隐藏。

## AI 边界

AI 智能体可以解释观测到的偏差，或提出部署计划。它不能重新定义哪一方是权威。未来暴露给智能体的任何命令，都使用与人员或 API 客户端相同的受治理作业流程。
