# 预发布 CloudLink MQTT v1

> 权威来源：[AetherCloud](https://github.com/EvanL1/AetherCloud/blob/main/docs/reference/cloudlink-mqtt-v1.md)。此页面镜像到统一的 AetherIoT 文档中。

这是一个实验性的预发布互操作候选方案。公开的 AetherContracts `v0.1.0-alpha.3` 版本是唯一的契约权威，AetherCloud 和 AetherEdge 提交了同一份按摘要固定的使用方锁定文件。当前的声明是已完整采用分发包并执行公开测试夹具，不是生产协议一致性。共享消息代理的生产密钥生命周期仍未解决，alpha.3 的持久 ACK 明确不带签名。

## 公开版本的使用

离线使用方检查固定了带注释的标签对象、提交、分发包大小和 SHA-256、发布清单 SHA-256，以及每个已采用目标的字节。它导入确切的 alpha.3 采用闭包，包括规范性规格、配置档、门槛、故障分类、TCK 清单、结构定义、测试夹具和验证器闭包。`pending_imports` 为空。

本地的 `contract-manifest.json`、`wire-profile.json`、身份验证结构定义、门槛文件和场景是集成历史或 AetherCloud 提案。它们不能覆盖 AetherContracts。仅有分发完整性并不等于编解码器或行为一致性。完整的公开测试夹具和需显式启用的双端测试工具现在提供 alpha 证据，而身份验证和生产持久存储门槛仍未通过。默认检查离线运行；需显式启用的 CI 检查只下载按摘要精确固定的那个版本。

## 已实现的云端接口

- `adapters/cloudlink/mqtt` 严格解码已固定的公开 snake_case 会话、心跳、运行时清单、遥测和数据丢失上行消息，并编码会话、心跳／持久 ACK 和重放下行消息。
- 编解码器校验主题／消息体的网关绑定、UUID 身份、规范整数／时间、JCS 业务摘要、运行时清单校验和、点位类型、拓扑证据、限制和未知字段。
- MQTT.js 接受可配置的端点、消息代理凭据、严格的 CA／客户端证书／私钥文件 mTLS、MQTT 3.1.1 或 MQTT 5、QoS 1 和 `retain=false`；正确性只依赖 3.1.1 基线。TLS 文件必须是有界的常规非符号链接文件，私钥必须拒绝组／其他用户访问。
- `apps/cloudlink` 通过现有的应用用例路由，没有应用回执就不产生 ACK。对于遥测，桥可以消费由 `PostgresTelemetryRepository` 提交的确切 ACK 投影；当前的消息代理测试工具组合根仍使用内存，属于一致性证据，不是生产耐久性。
- 当前的云端遥测模型只能安全地映射单样本的线上批次，因为它按记录建立索引，而 alpha.3 定位的是一个原子批次。在云端冻结这一内部映射之前，更大的批次会显式失败。数据丢失的持久化同样在规划中；alpha 测试工具记录一条应用事实，但不声明生产耐久性。
- 默认测试不需要消息代理、Docker、PostgreSQL 或云帐户。需显式启用的 alpha 测试工具会启动真实的 Mosquitto、AetherEdge 的 rumqttc 传输和文件型待发送队列，以及 AetherCloud 的 MQTT 入口和应用用例。

## 暂定的线上边界

规范性的公开核心位于已锁定的 AetherContracts 版本中。本地的 `contracts/cloudlink/v1/wire-profile.json` 记录的是较早的云端提案和迁移差异；它不是共享权威：

- 封闭的 snake_case UTF-8 JSON，最大 256 KiB；
- MQTT 3.1.1、QoS 1、非保留消息；
- 规范的 uint64 字符串和 Unix 纪元毫秒；
- 小写 UUID 的网关／会话身份；
- 每个原子批次一个流位置，最多 256 个点位样本；
- 只对 `{protocol_version,message_kind,payload}` 计算 RFC 8785 JCS SHA-256；
- 重放前后纪元、位置、批次 ID 和摘要保持稳定；
- 持久 ACK 绑定到会话、流、纪元、位置、批次、摘要和云端回执；
- 显式的重放请求和数据丢失证据；
- 没有 RPC、物理控制主题、SHM 写入、点位／寄存器写入，也没有伪造的物模型修订版。

遥测保留由边缘拥有的 `instance_id`、`point_kind`、`point_id`、值、源时间戳、质量和拓扑证据。`model` 是可选的，只有在投运时已经确立的情况下才可以出现。

## 会话与共享消息代理边界

alpha.3 的 hello 声明 `gateway-signed` 或 `trusted-connector-broker-attestation` 来源。网关签名的 hello 携带确切的质询 ID、网关密钥 ID 和经过结构校验的 Ed25519 签名对象。经过评审的 AetherContracts v1alpha1 身份验证配置档还定义了质询请求，以及质询和会话建立的确切 JCS 转录文本。

实验性的云端实现现在会解码质询请求、检查确切的活动已投运凭据声明、创建强 UUID 和 32 字节随机数、施加较短的 TTL 和固定的逐网关请求窗口、先持久化再发布，并使用独立引用的云端 Ed25519 密钥签名。未过期的完全相同重试会返回已持久化的质询字节。与之匹配的 hello 会验证独立引用的网关密钥、确切的请求／质询绑定和严格的到期时间，并以原子方式消费该质询、隔离同一范围内的前一个会话，并打开或重放一个会话。质询、hello 和接受消息发布失败时会保留已提交的状态，供完全相同的重试使用。凭据标识符、随机数、签名和原始转录文本不会出现在结果错误和应用请求标识符中。

这是握手证据，不是完整的生产消息来源身份验证。当前的凭据和公钥查找没有与质询消费以原子方式一起加锁，因为生产凭据／密钥生命周期尚不存在。因此，与接受过程竞争的吊销或轮换是一项明确的实验性 TOCTOU 限制。当其他发布者之后仍能向共享命名空间注入消息时，一次成功的 hello 也是不够的。

因此，通用的客户自选消息代理模式在已实现的、重放有界的握手之后，仍然要求每条业务上行消息都带有与会话绑定的网关签名。这一逐条上行消息的依赖尚未实现，所以网关签名的会话可以收到 `session-accepted`，但之后所有业务上行消息都以失败关闭方式被拒绝，不会调用应用命令。Alpha.3 的持久 ACK 仍然不带签名。

MQTT 主题身份不可信。单独的受信连接器配置档是显式的，并且默认拒绝：只有在配置的外部解析器提供了匹配的带外证据时，受信的消息代理证明才能打开会话。hello 签名绝不会被重用为凭据证明，载荷自带的证明仍然不可信。生产级的逐次发布受信适配器证据、密钥供应、轮换、吊销、验证者归属和消息代理资格认定仍是未通过的门槛。

| 模式 | 要求 | 状态 |
| --- | --- | --- |
| 可达的客户自选消息代理 | 专用命名空间、TLS、质询／逐条消息证明 | 实验性握手已实现；在逐条消息证明就绪之前，业务上行消息以失败关闭方式被拒绝 |
| AetherCloud 托管的消息代理 | 相同的 CloudLink 应用／会话边界 | 消息代理产品／主体集成在规划中 |
| 客户私有消息代理 | 保留身份、待发送队列／ACK 和审计的站点连接器 | 规划中 |
| 旧版 AetherEdge MQTT | 独立命名空间，绝不悄悄按 CloudLink 解码 | 迁移期间保留 |

MQTT PUBACK 只是传输证据，绝不授权从 AetherEdge 待发送队列中删除内容。

## 证据与剩余门槛

使用方锁定文件固定了完整的公开清单：全部 25 个公开测试夹具的字节在两个产品中都得到执行，待处理的导入为空。本地的测试夹具／门槛文件只是证据叠加层。

| 门槛 | 状态 |
| --- | --- |
| 共享消息代理的消息来源身份验证 | 实验性 v1alpha1 握手已实现；逐条上行消息证明和密钥生命周期受阻 |
| 单一的信封／时间／身份／摘要／不签名 ACK 配置档 | alpha.3 已实现；生产身份验证仍是实验性的 |
| 跨仓库测试夹具 | alpha.3 公开清单已通过 |
| 真实消息代理上的边缘／云双端测试工具 | 本地 Mosquitto 和 AWS IoT Core 的 alpha 证据；身份验证门槛仍是提案 |
| ACK 丢失、重启、重复、冲突和数据丢失故障注入 | alpha 证据已实现；不包括进程崩溃耐久性 |
| PostgreSQL 崩溃耐久的 ACK／发件箱 | 遥测接受的 PostgreSQL 切片已实现并验证；完整门槛受阻 |
| 旧版切换 | 在前面每一项门槛通过之前受阻 |

遥测接受事务、确切的 ACK 发件箱和有界的投递用例已经实现。完整的崩溃耐久 CloudLink 门槛仍然受阻：生产组合在规划中，原子的凭据／密钥生命周期、逐条上行消息身份验证、数据丢失事实、多样本映射和 alpha.3 生产身份验证仍未完成。旧版仍是默认值。云端中断不能改变边缘权威，也不能停止采集、规则、告警、安全联锁或本地控制。这个切片中没有物理控制。

## 需显式启用的边缘／云双端 alpha 测试工具

```bash
pnpm test:cloudlink-dual
```

该命令选择一个唯一的主题前缀，启动并重启本地 Mosquitto，运行两个产品的传输，并把机器可读的证据写入 `evidence/cloudlink-alpha3-dual-harness.json`（以及 `artifacts/cloudlink-alpha/evidence.json` 下的兼容副本）。它覆盖 ACK 丢失、独立的边缘进程恢复、由云端拥有的 `manifest/1/1` 续传游标、独立的云端入口进程重启、完全相同的重复重放、摘要／批次冲突、显式数据丢失、乱序、到期和一次非持久的部分应用结果。它把云端重启的连续性记录为未知；它不能证明生产环境的进程崩溃耐久性。当前行为和生产限制见 [CloudLink 可靠传输与生命周期](/zh/aethercloud/concepts/cloudlink-and-core-state-machines)。协议兼容性和版本固定请使用公开的 [AetherContracts 兼容性指南](/zh/aethercontracts/compatibility)。

## 需显式启用的 AWS IoT Core mTLS 测试工具

```bash
pnpm test:cloudlink-aws-iot
```

这项外部服务测试需要一个经过身份验证并具有 AWS IoT 权限的 AWS CLI 身份。它默认使用 `us-west-2`，可以通过 `AETHER_CLOUDLINK_AWS_REGION` 显式改到其他区域。该命令供应两个相互独立的 X.509 客户端主体和两个最小权限的主题策略，不创建任何 Thing，通过 8883 端口上的 AWS IoT Core MQTT 3.1.1 运行 AetherCloud MQTT.js 入口和 AetherEdge rumqttc/FileCloudLinkSpool，并把脱敏后的证据写入 `evidence/cloudlink-aws-iot-us-west-2.json`。

证书和私钥字节保留在权限模式为 0700 的临时目录中；各个文件使用模式 0600，不会进入 stdout、证据、Git 或应用日志。在每一条正常的成功或失败路径上，测试工具都会分离策略、停用并删除两个证书、删除两个策略，并移除临时目录。

这次 AWS 运行覆盖会话建立、心跳、运行时清单、遥测应用 ACK、ACK 丢失后的重放、重复消息的幂等性、冲突的绑定、到期、乱序投递、不受支持的部分批次、显式数据丢失和最终的待发送队列排空。它证明了经由托管消息代理的 alpha 传输互操作性。它没有通过生产身份验证门槛：应用尚未消费经过评审的带外 AWS 主体证明，也没有验证规划中的逐条上行消息网关签名。Alpha.3 的 ACK 仍然不带签名，云端持久化仍是进程本地内存。
