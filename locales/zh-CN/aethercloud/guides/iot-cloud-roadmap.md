# 物联网云垂直切片路线图

> 权威来源：[AetherCloud](https://github.com/EvanL1/AetherCloud/blob/main/docs/guides/iot-cloud-roadmap.md)。此页面镜像到统一的 AetherIoT 文档中。

每个阶段都必须可以运行并且有价值，而不能假装后续阶段已经存在。借助端口、内存适配器和契约测试夹具，默认验证路径始终不依赖 PostgreSQL、云账户和真实的 AetherEdge 设备。

## 第 0 阶段：审查与架构契约

**可观察价值**：开发者和智能体能够区分可执行层和已评审的契约，找到每一条权威边界，并选择下一个切片，而不会把多云基础设施工作当作物联网产品。

**模型**：限界上下文、权威矩阵、能力图、实现状态、状态机、存储归属和组合根依赖规则。

**API 与协议**：机器可读的能力、权限、错误、事件和 HTTP 操作目录。没有新的运行时端点或 CloudLink 线路消息。

**持久化**：分配了 PostgreSQL、对象存储、分析、收件箱/发件箱、审计和 OpenTelemetry 各自的职责，但不安装任何服务。

**安全**：边缘权威、租户隔离、默认拒绝的命令、敏感数据排除，以及对已实现/规划中状态的如实表述，都是文档契约。

**测试**：清单与 frontmatter 的一致性、链接、必需资产、目录结构定义、命令元数据，以及遥测与可观测性的分离。

**完成标准**：有证据支撑的审查、能力图、状态机、ADR、路线图和智能体索引彼此一致，并且文档契约测试通过。

**不包括**：运行时代码、提供商扩展、OpenTofu Apply、生产基础设施或臆造的边缘协议。

## 第 1 阶段：网关身份与登记基础

**可观察价值**：获得授权的操作员可以在一个租户和项目中注册网关、签发一份短期声明、让运行时认领它，并通过应用用例查询由此产生的状态。

**模型**：`TenantId`、`ProjectId`、`GatewayId`、`EnrollmentClaimId`、`EnrollmentRequestId`、`GatewayIdentity`，以及 `registered -> awaiting-claim -> claimed` 状态机。

**API 与协议**：已实现传输中立的注册、签发、认领和获取能力。目前还没有公开 HTTP 路由或 CloudLink 消息。

**持久化**：已实现乐观并发的存储库端口、内存存储库、内存令牌服务，以及 PostgreSQL 网关存储库/迁移。SQL 适配器提供租户 RLS，以及聚合/审计/发件箱的原子写入。生产数据库组合、角色、迁移执行、备份/恢复和 KMS 令牌服务仍在规划中。

**安全**：租户范围的权限检查、签发时的显式确认、服务端到期、幂等冲突、令牌以摘要形式静态存储、原始令牌只返回一次、统一的认领拒绝，以及要求审计的元数据。

**测试**：ID 解码、状态迁移、到期边界、完全相同的重放、冲突的认领、默认拒绝的权限、确认、跨租户查询、乐观替换、令牌验证和完整的内存流程。

**完成标准**：小范围测试、`pnpm check`、覆盖率阈值和生产依赖审计全部通过；智能体文档准确说明已实现的接口。

**不包括**：CA/KMS、生效凭据、吊销、恢复、证明、生产数据库部署、HTTP 登记、CloudLink 或设备控制。

## 第 2 阶段：CloudLink 心跳与会话

**当前状态**：传输中立的领域/应用/内存基础已经实现了通过端口进行的凭据验证、协议选择、无损的纪元/游标、隔离、恢复、心跳和会话查询。实验性的 JSON/MQTT 编解码器、消息代理适配器、应用桥、入口生命周期、结构定义、测试夹具和真实消息代理测试工具也已实现。生产凭据生命周期、共享的 AetherEdge 一致性测试、超时调度器、PostgreSQL 会话/纪元状态、持久的数据丢失事实、多实例归属和背压仍在规划中，因此第 2 阶段尚未完成。已接受遥测的 PostgreSQL 收件箱/游标/回执/ACK 事务和投递用例已经实现，但它们并不构成完整的会话持久性。生产发布顺序是：共享消息代理的来源身份验证、一份联合线路配置、完全相同的测试夹具、Edge/Cloud 双端消息代理测试工具、故障注入、崩溃后仍持久的 ACK 持久化，然后是显式的旧版切换。目标配置还不是已实现的编解码器。

**可观察价值**：操作员能看到经过身份验证的连接新鲜度，网关重连时不会重放已经持久化的信封。

**模型**：`CredentialBinding`、`SessionEpoch`、`ProtocolVersion`、`StreamCursor`、`HeartbeatObservation`、`IngressInbox` 和流量控制额度。

**API 与协议**：临时的实验性核心绑定实现了会话 hello/accepted、心跳/ACK、运行时清单、点位遥测、持久 ACK、重放请求和数据丢失的线路格式。alpha.3 的 ACK 没有签名。生产环境的质询/逐条上行身份验证仍然受阻；未来由 Cloud 签名的 ACK 需要一个新的协议版本。数据丢失的持久化、多样本的 Cloud 索引和额度消息需要后续的应用层工作。只读会话查询已经使用应用用例。

**持久化**：已接受遥测的 PostgreSQL 收件箱、游标、回执、审计、集成发件箱和精确 ACK 发件箱已经实现。PostgreSQL 会话、纪元、数据丢失和多实例归属仍在规划中；套接字状态仍然只存在于独立的 CloudLink 组合根本地。

**运维可观测性**：中立的、故障隔离的入口观察者已经实现。需要把它接到现有的空操作/OpenTelemetry 运行时上，带上可选的 W3C Trace Context、活跃会话与握手指标以及有界导出。默认不需要 Collector。

**安全**：凭据验证器端口、吊销检查、新会话隔离、协议允许列表、有界的消息/窗口限制、规范的 uint64 字符串、经过身份验证的按网关消息代理 ACL，以及来自已评审连接器/消息代理适配器的可选带外已验证主体元数据。当前的 hello 证明只是结构性的。通用的共享消息代理模式要求一个双方共同冻结的建立签名，以及每条上行消息上绑定会话的网关签名；可信的逐次发布消息代理证明是经过评审的替代方案。主题或载荷中的身份绝不提供授权。精确的签名投影、密钥轮换和吊销仍是门槛。

**测试**：两个仓库先关闭每一项待处理的 AetherContracts 导入，并执行完整且完全相同的有效/无效测试夹具集。然后由一个真实的消息代理运行 Edge 测试工具和 Cloud 入口，同时注入断连、ACK 丢失、Edge/Cloud 进程重启、重复投递、冲突摘要和数据丢失。单元覆盖另外包括缺口、乱序窗口、旧纪元、并发连接、背压、心跳超时、缺失追踪上下文、禁止用 baggage 授权、脱敏和导出器丢失。

**完成标准**：独立的 CloudLink 根和 AetherEdge 测试工具从 PostgreSQL 持久游标恢复；提交前崩溃不发出任何 ACK；提交后崩溃重新发布一条稳定且完全相同的 ACK；并且每一道按顺序排列的互操作门槛都通过。不依赖外部服务的默认测试套件仍然单独可用。

**不包括**：制品交付、任意 RPC、物理命令、直接写 SHM 或写设备寄存器。在本阶段完成之前，旧版仍是默认。

## 第 3 阶段：运行时清单与能力目录

**当前状态**：有界的 AetherEdge 运行时清单 v1 上报/查询切片已在领域、应用、Node 校验和以及内存存储库各层实现。它验证精确的外部字段，验证 AetherEdge 规范 JSON SHA-256 向量，从生效凭据推导范围，保留无损的代次和迟到的历史，拒绝有冲突的复用，并暴露当前的能力目录。PostgreSQL、持久的审计/发件箱、CloudLink 线路传输、公开的机群 API、新鲜度策略以及实例/点位目录仍在规划中，因此第 3 阶段尚未完成。

**可观察价值**：操作员和部署规划者可以查询运行时版本、上报的实例/点位元数据和支持的边缘能力，并附带观测时间和新鲜度。

**模型**：已实现 `RuntimeManifestObservation`、`ManifestGeneration` 以及能力/协议目录值；规划中的有 `RuntimeVersion`、`InstanceDescriptor`、`PointDescriptor`、`CapabilityDescriptor`、`ManifestGeneration` 和新鲜度。

**API 与协议**：已实现传输中立的上报命令和当前清单查询。版本化的清单观测信封、公开的机群/版本查询，以及带类型化谓词的动态分组仍在规划中。

**持久化**：已实现用于一致性测试的原子内存最新值/历史与请求重放适配器。PostgreSQL 最新值/历史元数据在规划中；只有当有界的关系型存储不够用时才考虑对象存储。

**安全**：经过身份验证的网关绑定、结构定义/版本验证、数量与大小配额，并且云端不变更已投运的边缘通道。

**测试**：重复代次和旧代次、乱序、未知能力、不受支持的版本、超限大小、过期投影和租户隔离。

**完成标准**：机群查询返回能力来源、`observedAt` 和新鲜度；部署兼容性检查可以使用该应用契约。

**不包括**：制品发布、分批发布、作业执行或通用的实体/关系/属性存储。

## 第 4 阶段：物联网遥测接入

**当前状态**：协议中立的领域/应用切片、规范摘要、内存收件箱/历史/发件箱/审计适配器、持久回执、重复与冲突重放处理、缺口/合并行为、配额、限定范围的历史查询、OpenTelemetry 接入装饰器、边缘原生的点位身份、拓扑绑定，以及实验性的 CloudLink MQTT 映射都已实现。PostgreSQL、已接受事实/历史/游标存储、审计/集成发件箱、精确 ACK 发件箱和有界的投递用例也已实现，并在 PostgreSQL 18 上完成验证。公开 HTTP、生产数据库/工作进程组合、数据丢失的持久化、多样本映射、降采样和导出仍在规划中，因此生产阶段为部分实现。

**可观察价值**：租户可以查询重放安全的点位与设备事件历史，而不会把它和权威的边缘实时状态混淆。

**模型**：`TelemetryStream`、`TelemetryBatch`、`PointSample`、`DeviceEvent`、`StreamEpoch`、无损的 `StreamPosition`、`IngestionReceipt`、`RetentionClass` 和缺口标记。

**API 与协议**：协议中立的接入和历史查询，以及实验性的版本化 MQTT 信封已经实现。该信封仍是预发布候选。持久 ACK 在应用接受之后发出；桥可以使用 PostgreSQL 中持久化的精确投影，而身份验证和生产组合仍受门槛限制。

**持久化**：PostgreSQL 收件箱、游标、元数据、配额、初始的有界历史、审计、集成发件箱和精确 ACK 发件箱已经实现；在有充分理由时，原始/冷批次可以通过可替换的历史存储端口迁移到对象存储。

**安全**：由凭据推导的租户/网关范围、解压与批次限制、规范的 int64 编码、配额、保留、载荷解码和显式新鲜度。OpenTelemetry 标签不包含资源身份。

**测试**：有效/无效批次、已吊销的网关、重放、同 ID 冲突、缺口、乱序、原子批次失败、int64 边界、提交前/后崩溃、断连、保留溢出、导出器故障隔离和历史查询。

**完成标准**：ACK 在持久接受之后发出；重放不产生重复的事实或事件；历史暴露源时间/接入时间、位置、质量和已知缺口；没有任何代码把它呈现为实时权威。

**不包括**：云端实时状态权威、云端确定性规则、高基数的点位指标，或者声称实验性结构定义是已发布的跨仓库契约。

## 第 5 阶段：告警投影

**当前状态**：边缘告警事实的领域投影、经过身份验证的接入、租户查询、仅云端的确认、规范摘要、重放/冲突/缺口/迟到行为，以及内存投影/审计/发件箱适配器已经实现。PostgreSQL、CloudLink 线路、公开 HTTP/搜索、指派、评论和新鲜度对账仍在规划中，因此生产阶段为部分实现。

**可观察价值**：租户可以搜索重放安全的边缘告警事实，并管理仅云端的确认、指派和评论，而不改变边缘安全状态。

**模型**：`AlarmOccurrence`、`AlarmFact`、`AlarmProjection`、边缘代次与序列、工作流确认、指派、评论和新鲜度。

**API 与协议**：经过身份验证的告警事实接入、告警搜索/时间线，以及通过共享应用用例执行的云端工作流命令。

**持久化**：PostgreSQL 收件箱、仅追加的事实、投影、工作流、审计和发件箱。

**安全**：网关绑定、有界载荷、租户隔离、云端工作流权限，并且没有任何云端操作可以清除本地告警或联锁。

**测试**：重复/冲突的事实、先清除后触发、缺失前序事实、迟到更新、断连后的过期状态、再次触发的代次、跨租户查询、工作流审计和投影重试。

**完成标准**：每个投影都暴露完整性和新鲜度，边缘事实状态与云端工作流保持分离，并且重放是幂等的。

**不包括**：以云端为权威的确定性告警、变更物理联锁，或通过 CloudLink 清除告警。

## 第 6 阶段：制品注册表

**当前状态**：显式的制品/修订版领域生命周期、无损的修订版/内容长度值、不可变发布、兼容性与依赖元数据、摘要/内容验证端口、签名验证器端口、发布通道冲突保护、发布/查询用例，以及原子的内存元数据/内容/审计/发件箱适配器已经实现。PostgreSQL、生产对象存储、由 KMS 支撑的签名验证、上传 HTTP、弃用/撤回命令和边缘下载仍在规划中，因此生产阶段为部分实现。

**可观察价值**：团队可以发布不可变、可验证的 Pack、配置、模型、规则和应用修订版，并附带来源证明和兼容性信息。

**模型**：`Artifact`、`ArtifactRevision`、`ContentDigest`、`Signature`、`CompatibilitySpec`、`ReleaseChannel` 和 `Publication`。

**API 与协议**：上传/完成、验证、发布、弃用、撤回、通道更新和读取/查询 API。边缘下载协议仍然按摘要引用，而不是内联可变内容。

**持久化**：PostgreSQL 存元数据；对象存储存 blob、签名、SBOM 和来源证明；发布事件使用事务性发件箱。

**安全**：摘要验证、不可变写入、签名者/来源证明策略、恶意软件/内容验证钩子、上传限制和需要权限的发布。

**测试**：被篡改的上传、重复摘要、验证失败、签名失败、发布竞争、冲突的幂等请求、通道竞争和撤回。

**完成标准**：已发布的修订版不可变、可独立验证，并且足够稳定，可以被期望状态引用。

**不包括**：发布调度或边缘激活。

已实现的层级契约和剩余的生产边界详见[制品注册表与不可变发布](/zh/aethercloud/concepts/artifact-registry)。

## 第 7 阶段：期望、报告与已应用部署

**当前状态**：单网关的领域/应用/内存基础已经实现。它验证已发布的制品，创建无损的期望代次，让报告与已应用保持分离，对边缘观测进行身份验证，把超时表示为未知而不产生已应用事实，保留迟到的观测，支持暂停/恢复/取消请求以及以新代次形式进行的回滚，并原子地记录内存审计/发件箱证据。PostgreSQL、持久的审计/发件箱、目标快照、金丝雀/分批调度、CloudLink 线路、HTTP 和 AetherEdge 交付仍在规划中，因此生产阶段为部分实现。

**可观察价值**：操作员可以执行金丝雀/分批发布、暂停/恢复、取消剩余目标、通过新代次回滚，并看到如实的偏差和部分成功。

**模型**：`Deployment`、`Rollout`、`TargetSnapshot`、`DesiredGeneration`、`ReportedRevision`、`AppliedEvidence`、发布策略和目标结果。

**API 与协议**：启动/暂停/恢复/取消请求/回滚命令、偏差查询、不可变修订版的下发，以及边缘端的接受/拒绝/获取/验证/应用观测。

**持久化**：PostgreSQL 聚合、目标状态、收件箱/发件箱和审计；对象存储存大型证据。

**安全**：制品兼容性、目标快照、权限/风险/确认、到期、前置条件和防 TOCTOU 的策略检查。

**测试**：旧报告、重复的期望代次、部分成功、断连后未知、取消竞争、暂停期间的交付、迟到的已应用证据、回滚，以及发布期间的目标替换。

**完成标准**：期望、报告和已应用可以分别查询，并且没有任何中间交付状态被呈现为已应用。

**不包括**：通用的边缘能力命令。

已实现的边界见[期望、报告与已应用部署](/zh/aethercloud/concepts/desired-reported-applied-deployment)。

## 第 8 阶段：受治理能力作业

**当前状态**：以能力为准入条件的领域/应用/内存基础已经实现。它从声明推导治理要求，要求平台权限和能力权限，支持确认/排队/下发/未知/取消，跨缺口对无损的边缘回执排序，把接入绑定到生效的网关凭据，并原子地记录内存审计/发件箱证据。PostgreSQL、运行时清单声明来源、CloudLink 交付、工作进程、公开 HTTP、证据存储和 AetherEdge 对应实现仍在规划中，因此生产阶段为部分实现。

**可观察价值**：租户先运行低风险诊断，之后再通过同一个可审计的作业生命周期运行经批准的命令，并保留边缘端的拒绝。

**模型**：`CapabilityDeclaration`、`CapabilityJob`、`Risk`、`Confirmation`、`Precondition`、`ExecutionAttempt`、`Receipt` 和证据引用。

**API 与协议**：创建、确认、下发、取消请求、状态和回执接入。能力结构定义来自运行时目录；没有任意 RPC。

**持久化**：PostgreSQL 作业账本、不可变的回执收件箱、审计和发件箱；对象存储存大型证据。

**安全**：权限、风险、确认、幂等性、到期、前置条件、审计、边缘侧接受，以及显式的非幂等未知语义。

**测试**：缺失治理元数据、权限/确认失败、前置条件漂移、重复请求、冲突的重复请求、边缘拒绝、超时、迟到的回执、重试、取消竞争、部分结果和网络分区。

**完成标准**：从创建到最终回执有一条相互关联、不可变的审计链，并且不存在任何传输层旁路。

**不包括**：默认启用的物理控制；此类能力仍然默认拒绝，并需要额外的策略证据。

已实现的边界见[受治理的能力作业](/zh/aethercloud/concepts/governed-capability-jobs)。

## 第 9 阶段：审计、查询、集成、运维与可观测性

**当前状态**：租户/项目范围的审计值与游标查询、需要身份验证的 JSON 路由、有限的可通过 `Last-Event-ID` 续传的 SSE 快照、webhook 订阅以及有界的投递/重试/死信/重新投递状态机、异步数据导出的请求/结果/查询，以及内存适配器已经实现。PostgreSQL 持久性、生产身份、实时通知、目的地注册表/密钥/签名/SSRF 防御、工作进程、对象存储、下载、配额、机群健康和 WebSocket 仍在规划中，因此第 9 阶段为部分实现。

**可观察价值**：操作员可以搜索完整的操作历史，监控连接/数据/部署/作业的健康状况，并安全地订阅、导出或投递 webhook。

**模型**：`AuditEvent`、`FleetHealthProjection`、`Subscription`、`WebhookEndpoint`、`DeliveryAttempt`、`DeadLetter`、`ExportJob`、`Quota` 和 `RetentionBudget`。

**API 与协议**：按租户过滤的审计/机群查询、SSE/WebSocket 事件续传、webhook/订阅/导出命令，以及死信重新投递。

**持久化**：PostgreSQL 审计/发件箱/投递和汇总状态；对象存储存导出文件；可选的 OpenTelemetry 追踪/指标后端；只有在实测确有需要之后才使用消息代理。

**安全**：仅追加的审计、脱敏、webhook 的 SSRF 防护与签名、密钥轮换、按租户过滤的流、配额和速率限制。

**测试**：跨租户搜索、重复投递、指数退避重试、死信、重新投递、流断连/续传、webhook 轮换、配额、保留、投影新鲜度、追踪传播、脱敏、指标基数、有界导出和导出器故障隔离。

**完成标准**：此前所有的命令和接入路径都能在审计中关联起来，健康视图暴露源时间和新鲜度。

**不包括**：没有实测运维证据支撑的 Kafka、Redis、Kubernetes 或服务拆分。

## 第 10 阶段：MCP 资源与工具

**当前状态**：传输中立的 MCP 接口可以列出能力和审计资源，通过 `SearchAuditEvents` 读取租户审计证据，公布完整的治理元数据，并通过现有应用命令暴露 `data.export.request` 和 `edge.job.create`。规划中的工具以失败关闭方式拒绝。MCP SDK 传输、stdio/Streamable HTTP 组合根、生产身份/审计、速率限制以及其余资源/工具仍在规划中，因此第 10 阶段为部分实现，目前还没有任何 MCP 客户端能够连接到线路服务器。

**可观察价值**：编码智能体和运维智能体读取真实的产品契约、能力元数据和租户投影，然后只调用已有的受治理用例。

**模型**：`DocumentationResource`、`CapabilityDefinition`、工具输入/输出结构定义、参与者来源和审计关联。

**API 与协议**：先提供只读的文档和查询资源。命令工具与已实现的应用命令一一对应，并在调用之前显示权限、风险、确认、幂等性和到期时间。

**持久化**：复用正常的应用端口和审计；没有智能体专用的数据路径。

**安全**：租户授权、最小权限、显式确认、提示词/输出脱敏、来源、速率限制和默认拒绝的发现。

**测试**：HTTP/CLI/MCP 用例一致性、拒绝规划中的能力、元数据完整性、跨租户拒绝、确认、机密脱敏和审计。

**完成标准**：智能体可以在调用之前确定已实现/规划中的状态和治理要求，并且每个工具结果都能追溯到同一个用例。

**不包括**：会写存储的聊天机器人、智能体专用的 CloudLink 路径或直接的物理控制。
