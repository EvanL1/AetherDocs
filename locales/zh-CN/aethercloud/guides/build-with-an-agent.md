# 使用 AI 智能体进行构建

> 权威来源：[AetherCloud](https://github.com/EvanL1/AetherCloud/blob/main/docs/guides/build-with-an-agent.md)。此页面镜像到统一的 AetherIoT 文档中。

AetherCloud 把架构、产品语义和已实现的接口记录为版本化的仓库资产，这样编码智能体可以做出范围很小的更改，而不必从框架代码中重建意图。

## 为智能体提供上下文

让智能体指向仓库根目录，并要求它依次阅读：

1. `AGENTS.md`：强制边界和验证要求
2. `skills/aether-cloud/SKILL.md`：任务路由
3. 从 `llms.txt` 中选出的页面
4. 最近的包 README 或契约：实现细节

涉及提供商的工作，在更改应用端口或编写 SDK 代码之前，还要阅读[添加提供商适配器](/zh/aethercloud/guides/add-provider-adapter)。

提示词示例：

```text
阅读 AGENTS.md 和 aether-cloud 技能。使用现有应用层边界增加只读提供商能力查询。
不要让提供商 SDK 类型进入应用层包；同时更新 HTTP 参考文档并运行 pnpm check。
```

## 要求提供证据

智能体应当指明：

- 它正在更改的事实来源
- 应用用例和权限边界
- 契约是已实现还是规划中
- 意图是提供商中立的，还是需要带命名空间的提供商特性
- 基础设施工作涉及的提供商、部署堆栈、状态和凭据边界
- 在实现之前会失败的小范围行为测试
- 之后通过的验证命令

拒绝以下生成代码：从路由处理器直接写适配器、把云端遥测当作实时权威、遗漏租户上下文，或臆造版本化契约包中不存在的 CloudLink 消息。

同样拒绝：核心包中写死的厂商分支、根据凭据内容推断提供商、跨提供商的状态、解析面向人的 IaC 输出，以及缺少已保存计划和批准证据的基础设施应用操作。

## 文档契约

每个被索引的页面都带有包含 `title`、`description`、`updated` 和 `status` 的 frontmatter。同样的标题、描述和状态也出现在 `ai/docs-manifest.json` 中。状态取值为 `implemented`、`planned`、`mixed`、`normative` 或 `deprecated` 之一。仓库测试会检查清单、本地链接、必需的入口点和未完成的占位符。

行为变化时，要更新代码、测试和对应的参考页面；如果清单描述的路由含义变了，也要更新清单描述。架构权威或依赖关系的变更还需要一份 ADR。

## 当前验证

```bash
pnpm check
```

该命令运行文档契约、单元与集成测试、类型检查、代码规范检查和格式检查，不需要外部服务。

## 智能体能力

仓库基础里程碑为编码智能体提供文档。远程 MCP 资源和运维工具规划在之后提供，要等身份、租户授权和底层查询用例具备之后。仓库文档不得指示智能体在这些工具发布之前调用它们。
