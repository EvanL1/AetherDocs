# aether-shm-bridge

带类型的组合桥接层，连接 Aether 权威的共享内存数据平面、仅供所有者使用的写入端口和只读的服务使用方。

桥接层把配置中确切的 `PhysicalPointAddress` 值编译成确定性的 `ChannelPointManifest`；稀疏的点位 ID 绝不会变成隐式的槽。点位平面中唯一的填充，是把通道的第一个 C/A 槽与其 T/S 缓存行错开对齐。`ChannelHealthManifest` 把配置的通道 ID 映射到紧凑排列的健康槽。两份清单各自的 `layout_hash`、精确槽数量、写入器世代和非零发布纪元共同构成一份协调的点位/健康提交见证。

拓扑变更会发布一个大小精确的新 inode，而不是调整活动映射的大小。桥接层只迁移带类型地址完全相交的部分；新增的点位以未写入状态开始，被移除的点位也不会通过被复用的槽索引泄漏状态。

`ShmAcquisitionStateWriter` 负责 T/S 写入，并保留值、原始值、时间戳和 `PointQuality`。受治理的命令下发只镜像 C/A。普通写入不会刷新存活状态；点位心跳和健康心跳由专门的 io 任务负责。只读的世代会拒绝过期或混杂的发布，并且只重连到服务拓扑所固定的物理身份。

`SlotSource::read_slots` 为整个批次固定一个读取器，校验一次心跳，并在批次前后对世代/发布做隔离检查。返回的每个槽都满足 seqlock 一致性，但整个批次并不是跨槽的原子快照。

PointWatch 使用各使用方独立的位图和 16 字节的 UDS 唤醒帧，帧中只包含通道 ID、点位 ID、槽索引和类型。自动化、告警和 API 会根据各自固定的清单校验地址/槽，然后重新读取 SHM；事件载荷从不具有权威性。位图容量是显式且带版本的，取自编译清单时使用的同一个部署资源上限，而不是库中的固定常量。

`ShmObserver` 无需 HTTP 或守护进程即可提供直接的只读可观测性。它根据物理身份、心跳时长和可选的聚合槽扫描，把已提交的点位/健康对评定为健康、降级或不健康；它绝不修复或写入任何一个平面。

默认的点位路径是 `aether-live-state.shm`。这个桥接层只接受 `aether-dataplane` 暴露的 v5 mmap 契约和快照 v1 契约；其中没有 v4 或更早快照的解码器。它不依赖 Redis 或 PostgreSQL，也绝不向读取使用方授予采集写入器的权限。

```bash
cargo test -p aether-shm-bridge
```
