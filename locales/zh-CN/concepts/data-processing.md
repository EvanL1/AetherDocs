# Aether 数据处理

Aether 数据处理是一项与行业无关的应用能力，用于把受治理的 IoT 观测数据变成经过校验的派生数据。它从 Aether 所拥有的数据源组装有界的输入帧，调用本地或远程处理器，校验响应，并通过同一个与传输无关的应用边界提供结果。版本 1 在 `aether-api` 中暴露带认证的 HTTP 路由；CLI 和 MCP 绑定尚未实现。未来任何传输、调度器或自动化集成都必须使用同一个应用边界。

预测是第一个数据处理任务。负荷预测的模型端点不是第二个数据平台，也不拥有站点的数据路径：它只是一个请求驱动的 `DataProcessor`，接收完整的 `ProcessingFrame` 并返回 `ProcessingResult`。

这项已经实现的内核能力并不会让数据处理成为必需的第七个进程，也不要求默认发行版中存在模型、云端连接或外部数据库。组合根可以在现有进程中运行该应用，也可以把它隔离到一个可选的、独立受监管的进程中。

## 术语

| 概念 | 名称 |
|---------|------|
| 架构能力 | Aether 数据处理 |
| 应用用例 | `DataProcessingApplication` |
| 配置的工作单元 | `DataProcessingTask` |
| 处理实现端口 | `DataProcessor` |
| 受治理、按时间对齐的输入 | `ProcessingFrame` |
| 不可信的处理器响应 | `ProcessingResult` |
| 经过校验的 Aether 结果 | `DerivedData` |

这个模块叫**数据处理**而不是预测，是因为未来的行业包除了预测之外，还可能需要窗口估计、特征派生、评分或分类。它不叫分析，因为它不是报表或 BI 界面；它也不以某种模型技术命名，因为确定性算法和模型端点实现的是同一个处理器契约。

## 哪些内容属于这里

数据处理任务具备以下全部性质：

- 它从已经解码、语义明确的 Aether 数据出发；
- 它在有界的帧和显式的 `as_of` 时间上运行；
- 它所需的字段、单位、时间策略、质量限制和输出结构定义在执行之前就已声明；
- 它通过请求/响应式的应用用例调用；
- 它产生的派生数据带有输入、处理器、质量和过期时间的出处；
- 它没有直接作用于设备的副作用。

例子包括 24 小时的站点负荷预测、基于一段振动窗口的剩余使用寿命估计、基于楼宇测量值的舒适度评分，或者对一个已完成生产周期的质量分类。第一个标准化的任务是 `Forecast`；之后的任务类型需要各自带类型的输入和输出契约，而不是藏在一个万能的 JSON API 里。

## 核心不变量

每个实现都必须保持以下性质：

1. **由数据方请求处理器**。`DataProcessingApplication` 组装并发送完整的输入。处理器不会回调 Aether 去发现站点、读取 SHM、打开历史数据库或获取任意点位。
2. **数据权威不转移**。SHM 仍是当前实时点位状态的权威，历史能力仍是已存储观测的权威，配置的协变量来源拥有各自的数据。处理只创建 `DerivedData`。
3. **输入以任务为范围**。任务和已投运的绑定决定可以读取哪些字段。调用方或处理器不能把一次处理请求变成不受限制的站点数据查询。
4. **处理器是计算适配器**。它们可以拥有算法代码、模型工件、特征顺序、缩放器、张量构造或远程 API 客户端。它们不拥有 Aether 的点位绑定、实时状态写入、告警生命周期、规划或设备控制。
5. **失败是显式的**。缺失输入、数据过期、处理器错误、无效输出和经批准的回退始终可以区分。技术性失败绝不能表示成零这样的正常值。
6. **派生数据不是测量状态**。结果保留其输入摘要、处理器出处、质量和过期时间。它们绝不会被写入归 IO 所有的 T/S 槽，也不会被悄悄提升为实时状态权威。
7. **热路径是独立的**。处理器或 AI 客户端不可用时，采集、确定性保护、告警和必要的控制继续运行。
8. **独立运行的配置保持独立**。Redis、PostgreSQL、云端处理器和模型服务仍是可选的下游组件，而不是 Aether 内核的启动依赖。

## 架构边界

```
authenticated HTTP / in-process application work
                    │
                    ▼
       DataProcessingApplication
        ├─ task + commissioned binding
        ├─ HistoryQuery
        ├─ read-only LiveState
        ├─ CovariateSource
        └─ frame and quality policy
                    │
                    ▼
            ProcessingFrame
                    │ complete request
                    ▼
             DataProcessor
          local algorithm / model
           sidecar / remote API
                    │
                    ▼
        untrusted ProcessingResult
                    │ validate and stamp
                    ▼
               DerivedData
        └─ v1 direct query response
```

这项能力是贯穿 Aether 现有各层的一个纵向切片：

- 领域层拥有任务标识符、时间范围、单位、数据质量、结果状态、处理器出处和 `DerivedData` 等稳定的值类型。
- 端口描述 `HistoryQuery`、`CovariateSource` 和 `DataProcessor` 这样的窄能力。它们不包含 SQL、HTTP、厂商、协议或张量运行时方面的词汇。
- 应用层解析任务绑定，组装并校验 `ProcessingFrame`，调用处理器，校验其结果，并应用授权、出口、截止时间和审计策略。
- 服务私有的适配器和下游适配器为本地算法、HTTP 模型边车、远程服务、天气数据或可选的派生数据存储实现这些端口。
- 行业包声明任务语义和特征角色。站点投运把这些角色绑定到具体的实例和点位。
- 组合根选择具体适配器，并决定处理是否需要进程隔离。核心 crate 绝不依赖某个行业包或下游处理器。

组装、请求、校验和失败的详细顺序，以及哪些可选的结果路径仍是未来的工作，见[数据处理流程](/zh/concepts/data-processing-flow)。

### 已实现的历史与时间语义

当前的生产组合在现有的 `aether-history.db` 之上使用以任务为范围的只读 `SqliteHistoryQuery`。它绝不创建或迁移历史库的表结构。一次处理请求的所有特征读取共享同一个 SQLite 事务/快照。对于区间末节奏 `c`，标签 `t` 聚合的是 `(t-c, t]` 内的原始观测；历史网格在 `as_of` 处结束，未来协变量和预测输出从 `as_of+c` 开始。

在生产环境中，只读的 SQLite 连接标志必须有操作系统权限作为支撑：通过独立的只读挂载或身份把历史数据库/WAL/SHM 目录暴露给 API，并与 API 可写的配置/审计存储分开。基础 Compose 中覆盖整个目录的 `/app/data:rw` 挂载不满足这项直接读取历史的投运门槛。

可选的 HTTP 历史适配器范围更窄：它只接受已经对齐到确切节奏网格、并且使用 `aggregation=last` 和 `duplicate_policy=reject` 的上游。它不聚合原始历史。

这里的 `as_of` 是事件时间的上界，而不是双时态的数据库截面。当前的 SQLite 行没有摄取/系统时间戳，也没有来源纪元、绑定纪元或配置纪元。一个事务能让一次调用在内部保持一致，但之后在更早的 `time_ms` 上的回填可能改变重放结果，而同一逻辑序列背后的重新映射可能把两个物理来源拼接在一起。当前的任务/绑定修订号无法弥补缺失的行纪元。因此，严格的历史评估需要在评估截面处捕获的冻结历史库快照，或者需要未来的 `HistoryQuery` 实现同时按事件时间和摄取/来源纪元过滤。

工件选择器同样记录身份、版本和摘要，但不记录 `trained_through` 或 `available_at`。固定的摘要使一次执行可以被识别；它并不能证明该工件在某个历史 `as_of` 时已经存在。在加入这些可用时间/训练截面之前，数据处理可以组装有界的在线帧和确定性的基准样本，但它本身并不提供不泄漏未来信息的历史模型回测。

### 当前的质量限制

领域层、线上契约和 SHM v5 实时路径都保留样本质量。实时读取把存储的来源质量与新鲜度策略结合起来，而不是把每个有限值都改写为 `good`。嵌入式历史的表结构仍然只存储数值观测而不带设备质量，因此历史帧以及历史/实时混合帧不能声称具有完整的端到端质量保真度。版本 1 还会强制检查间隙、缺失、数值约束、出处和协变量的发布时间。如果站点要求历史特征带有原始质量，就必须在启用任务之前投运一个带质量信息的历史来源。

## 任务、绑定和处理器的划分

`DataProcessingTask` 描述一个稳定的运行问题。对于预测，它包括目标语义、观测字段和未来协变量字段、回看窗口、预测范围、分辨率、工程单位、时区和符号契约、新鲜度限制、缺失数据策略以及带类型的输出契约。它不包含通道地址、SHM 槽、SQL 查询、张量节点、处理器 URL 或密钥。

行业包提供这份语义层面的任务定义。站点投运把它的字段绑定到具体的 Aether 实例和点位。`DataProcessor` 则单独拥有与算法相关的表示。这种划分使设备可以迁移到另一个通道而无需重建处理器，模型版本也可以更换而无需让 Aether 了解张量布局。

例如，能源包可以声明一个 `site-load-forecast` 任务，其目标是有功输入功率。已投运的站点把 `load` 绑定到某个实例测量，把 `temperature` 绑定到某个天气测量。负荷预测 HTTP 处理器随后把这些具名的列映射成其模型所需的特征顺序和缩放方式。模型端点在请求中收到数据；它不会收到一个 `plant_id` 再去查询第二个时序数据库。

概念上的处理器契约是：

```
DataProcessingRequest {
  request context + deadline,
  task and output contract,
  processor selection policy,
  ProcessingFrame,
  input digest
}
          │
          ▼
DataProcessor.process(...)
          │
          ▼
ProcessingResult {
  request and input identity,
  processor/artifact provenance,
  status + quality + expiry,
  task-typed processor output
}
          │ validate and Aether-stamp
          ▼
DerivedData {
  result and acceptance identity,
  validated task output + provenance
}
```

帧携带的是具名、带类型的字段，而不是处理器专用的张量或非结构化载荷。不可信的结果信封提供关联信息、出处、回退状态和过期时间。Aether 校验其带类型的输出，然后创建 `DerivedData`。这让数据路径保持可检查、可测试，并使固定下来的帧可以在离线一致性测试或基准测试中复用，而不把内核与某一种算法运行时耦合在一起。它并不承诺 API 重放。

## 预测是第一个任务

预测会走完整条跨行业的处理路径：

- 一个历史观测窗口；
- 可选的当前 SHM 尾部，仅用于以 `Last` 聚合的特征；
- 未来的或已知的协变量，例如天气、日历、电价或排程；
- 单位/符号兼容性、时区、对齐和重采样策略；
- 带有显式预测范围和过期时间的多步输出；
- 可选的分位数或置信区间；
- 基于确切组装出的帧和受治理上下文的内容身份，但并不意味着可变的数据源仅凭 `as_of` 就能重建它。

预测结果包含有序的未来时间戳、目标语义、单位，以及一个或多个值或分位数。通用信封还标明任务、输入摘要、处理器和工件版本、发布时间、过期时间、质量，以及是否使用了经批准的回退。

同一个 `Forecast` 契约可以支持不同的行业包：

| 行业包 | 预测示例 | 典型的观测和协变量 |
|---------------|------------------|--------------------------------------|
| 能源 | 站点负荷、光伏发电或需量 | 功率历史、天气、日历、电价 |
| 制造 | 生产需求或剩余使用寿命 | 周期计数、振动、温度、排程 |
| 楼宇 | 冷负荷或人员占用 | 区域传感器、天气、日历、预订排程 |
| 农业 | 灌溉需求或土壤湿度 | 土壤传感器、天气预报、作物排程 |
| 交通 | 交通流量或到达时间 | 计数、速度、线路排程、天气 |

之后可以增加其他处理任务类型，但每一种都必须定义带类型的语义和一致性测试。通用的 `process(json)` 后门不得成为公开的应用契约。

## 与相邻子系统的边界

“处理”这个词有意取得比较宽泛，因此必须明确它的界限。

| 相邻子系统 | 它的职责 | 数据处理的边界 |
|----------|--------------------|--------------------------|
| IO 解码 | 读取协议帧，校验线上值，应用通道点位解码，并发布规范的 T/S 值 | 只在值已经具有 Aether 点位身份和工程含义之后才开始；绝不解码 Modbus 寄存器、IEC 报文或原始帧 |
| SHM 数据平面 | 权威的当前点位值和现有的命令传输 | 通过 `LiveState` 只读输入；派生结果和处理器都不写入归 IO 所有的 T/S 槽 |
| 历史 | 采样、持久化、保留、聚合和查询观测 | 应用读取 `HistoryQuery`；默认适配器以只读方式打开现有的历史 SQLite 文件，而处理器永远得不到数据库访问权限 |
| 规则引擎 | 确定性的事件/节拍评估和动作执行 | 不取代规则，也不在规则热路径中同步调用网络处理器 |
| 告警服务 | 告警策略、生命周期、严重程度、确认和通知 | 可以把评分或检测结果作为 `DerivedData` 产出；它本身不创建或确认告警 |
| 批量 ETL / BI | 大范围扫描、任意联接、数据仓库、仪表盘和离线报表 | 为已声明的任务处理有界的运行帧，而不是通用数据管道或分析型数据仓库 |
| 规划 / 优化 | 把观测和派生数据变成拟议的运行计划 | 止于经过校验的派生数据；它不选择或调度设备动作 |
| 控制 | 授权、确认、审计、路由和下发设备命令 | 之后的调用方必须进入 `ControlApplication`；处理器输出不授予任何控制权限 |

当前的 v1 组合要求已投运的物理单位、比例、偏移和目标符号元数据与任务完全一致。它执行对齐和聚合，但不做运行时的单位/符号转换。未来显式的变换将创建一个任务专用的视图而不改变权威的测量值，并且需要自己的测试和出处。

## 数据权威

| 数据 | 权威 | 处理方式 |
|------|-----------|----------------------|
| 当前 T/S 点位值 | 归 IO 所有的 SHM | 通过 `LiveState` 读取；处理绝不写入 |
| 历史点位观测 | `HistoryQuery` 实现 | 通过端口读取；处理器绝不直接打开存储 |
| 外部或未来协变量 | 配置的 `CovariateSource` | 连同事件时间和发布时间的出处一起复制 |
| 任务和点位绑定 | 同步之后的 Aether 配置 | 在处理器请求之前解析 |
| 算法/模型工件和私有变换 | 所选的 `DataProcessor` | 作为处理器和工件出处返回 |
| 处理输出 | 经过校验的 `DerivedData` | 派生的、质量受限、会过期，并由 v1 API 直接返回 |
| 设备动作 | 现有的控制应用和分发器 | 只能由另一个独立的决策和控制用例创建 |

`ProcessingResult` 必须标明请求、任务和绑定修订号、输入摘要、处理器和工件版本、发布时间、过期时间、状态和质量。使用方会拒绝不受支持的契约版本、非有限值、不匹配的形状或单位、超出任务范围的时间戳、已过期的结果，以及无法与所提交的帧关联起来的结果。

## AI 原生治理

数据处理之所以是 AI 原生的，是因为任务契约、允许的输入、质量、处理器出处、权限、出口和失败状态都是机器可读的，而不是因为数据路径中有一个大语言模型。v1 带认证的 HTTP 接口调用 `DataProcessingApplication`；未来的 CLI、MCP 和定时接口必须调用同样的用例。

没有副作用的处理调用属于中等风险的查询，因为它配置的路由可能跨越远程数据出口边界；对于这条已批准的路由是否需要确认由部署策略决定，持久审计是必需的，并且该能力被标记为非幂等，因为每次调用都可能再次执行处理器工作。低风险的任务发现和处理器健康发现不需要确认或持久审计，因为它们不携带任何观测值。更改任务、路由、工件选择、出口策略或回退策略是一条独立的配置命令，有自己的权限、确认和审计元数据。处理结果绝不继承操作设备的权限。

远程处理器形成一条显式的数据出口边界。应用必须把处理器列入允许列表，把请求精简到任务声明的字段，强制执行载荷和截止时间限制，避免带出无关的标识符和密钥，并保留足够的出处，以解释某个结果是由哪个数据截面和哪个处理器产生的。

## 非目标

Aether 数据处理不是：

- 协议解码、采集、SHM 复制，或第二个实时状态平面；
- 时序历史库、特征存储、数据湖、ETL 引擎、BI 平台或任意查询服务；
- 训练管线、实验跟踪器或强制的模型注册表；
- 确定性规则、告警生命周期、规划、优化或 `ControlApplication` 的替代品；
- 允许处理器发现任意站点数据或查询 Aether 数据库的许可；
- 通用的张量传输或无类型的插件 API；
- 要求每个部署都运行一个数据处理进程；
- 采集或硬实时安全回路的一部分。
