# 依赖安全例外

安全公告默认一律拒绝。只有当受影响的操作不可达、边界在代码中强制执行，并且此处记录了移除条件时，才允许例外。

## RUSTSEC-2023-0071 (`rsa`)

- **引入来源**：`aether-io` 中可选的 `async-opcua` 支持。
- **风险**：上游的 RSA 实现可能通过计时侧信道泄漏私钥信息。
- **运行时边界**：`aether-io` 只接受使用 `SecurityPolicy::None` 和 `MessageSecurityMode::None` 的匿名 OPC UA 会话。签名、加密、用户名/密码认证和示例密钥对生成，都会在构造 OPC UA 客户端之前被拒绝。
- **默认暴露面**：无。`opcua` Cargo 特性默认禁用。
- **补偿控制**：凡是需要传输安全或认证的场合，使用可信且隔离的现场网络，或者使用单独经过审计的 OPC UA 桥接。
- **审计策略**：`deny.toml` 以及 CI/本地的 `cargo audit` 调用都只忽略 `RUSTSEC-2023-0071`；其他所有公告仍被拒绝。
- **移除条件**：一旦 `async-opcua` 不再解析到受影响的 `rsa` 版本，就移除 `cargo-deny` 和 `cargo-audit` 的例外以及临时的运行时限制；然后在重新启用这些模式之前，先添加带认证和加密的集成测试。
- **复查责任人**：维护者；每次更新 `async-opcua` 时复查，并且每个发布版本至少复查一次。

这项例外保留了协议互操作性，但并不声称受影响的加密操作是安全的。
